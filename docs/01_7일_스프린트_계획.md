## D1.6 — DogFaceNet 추가 (얼굴 클로즈업 대응)

animal.go.kr 실사진을 보니 보호소 사진의 약 1/3이 얼굴 클로즈업이라, MPDD(전신·포즈 위주)만으로는
부족할 수 있다는 우려가 나와 얼굴 전용 공개 데이터셋을 조사했다.

- **DogFaceNet** (Hugging Face `dimidagd/DogFaceNet_224resize`) 채택 — 승인 절차 없이 즉시 다운로드,
  MIT 라이선스, 75.9MB.
- **1,393개체 / 8,363장**, 이미 눈·코 랜드마크로 정렬된 224×224 얼굴 크롭.
  MPDD(191개체)보다 개체 수가 7배 많아 메트릭 러닝 일반화에 유리.
- 개체당 이미지 2~41장(중앙값 5장) — 얼굴 검증(verification) 데이터셋 특성상 개체당 샘플은 적지만
  개체 다양성이 큼. 공식 split이 없어 **개체 기준 80/20 (train 1,115 / test 278 ID) open-set 분할을
  직접 생성**했다 (`scripts/build_dogfacenet_manifest.py`, seed=42, ID 중복 없음).
- 샘플 확인 결과 얼굴 정렬 시 생긴 검은 모서리 패딩이 일부 있음 — 학습 시 random crop으로 완화.

**학습/평가 전략**: MPDD와 DogFaceNet은 서로 다른 실제 개체 집합이라 ID 네임스페이스만 분리하면 합쳐서
학습할 수 있다. **DogFaceNet을 메인 학습 데이터(개체 수 많음)로, MPDD를 포즈 강건성 파인튜닝·평가로
병행**한다. 최종 모델은 **두 벤치마크 모두에서 CMC/mAP를 따로 보고** — "얼굴 중심 데이터 vs 전신·포즈
다양 데이터"에 대한 교차 일반화 결과 자체가 보고서의 흥미로운 발견이 된다.

## D1.7 — 선행연구 반영: Triplet 대신 Prototypical Network

`docs/references/Yeon2025_FewShotDogFaceID_MetaLearning.pdf` (연수민 외, Journal of KIIT, 2025)를
검토했다. **정확히 우리가 쓰는 DogFaceNet**으로 실험했고, 개체당 이미지가 2~41장(중앙값 5장)으로
극히 적은 상황에서 일반 전이학습 파인튜닝(1-shot 18.3%)이 메타러닝 기반 소수샷 학습
(Meta-DeepBDC, 1-shot 64.0%)에 크게 뒤처짐을 실증했다.

우리 E1(CE 파인튜닝)이 이 논문의 "Baseline"과 같은 구조라, DogFaceNet처럼 개체당 샘플이 적은
데이터에서 비슷한 한계를 보일 가능성이 크다. → **E2를 Triplet loss에서 Prototypical Network
방식 에피소드 학습으로 변경**한다.

- 구현 부담 증가는 크지 않음: 이미 P개체×K장 에피소드 샘플링이 필요했던 Triplet과 달리
  ProtoNet은 hard negative mining 없이 **클래스 프로토타입(임베딩 평균)까지의 거리 기반
  softmax**만 있으면 됨 — 오히려 더 단순.
  - Meta-DeepBDC(공분산 기반, 논문 최고 성능)는 구현 난이도가 높아 **E3 스트레치**로 남긴다.
- 평가는 논문의 "20-way 분류 정확도"를 그대로 따르지 않고, **우리 서비스에 맞는 open
  retrieval(CMC/mAP)로 통일** — 학습 방법(손실 함수)만 논문 근거로 교체하는 것.
- 이 비교(E1 CE 파인튜닝 vs E2 ProtoNet) 자체가 "저샷 데이터에서 메타러닝이 유리하다"는
  선행연구 결과를 우리 방식(retrieval 지표)으로 재현하는 셈이라 보고서에서 인용 가능한
  탄탄한 실험 스토리가 된다.

## 축소된 실험 매트릭스

| # | 내용 | 목적 |
|---|---|---|
| E0 | ImageNet 사전학습 ResNet50 feature, 학습 없이 cosine kNN | 베이스라인 |
| E1 | ResNet50 + BNNeck + CrossEntropy 파인튜닝 (DogFaceNet+MPDD 통합 학습) | 일반 파인튜닝(논문의 "Baseline"과 동일 계열) |
| E2 | ResNet50 + **Prototypical Network 에피소드 학습** (P-way K-shot) | 저샷 메트릭 러닝 — 논문 근거로 채택 |
| E3 (스트레치) | Meta-DeepBDC(공분산 기반) 또는 저해상도·클로즈업 크롭 증강 | 시간 남으면 논문 최고 기법까지, 아니면 실사용 도메인 대응 |

모든 실험은 **MPDD test와 DogFaceNet test 양쪽에 대해 CMC Rank-1/Rank-5/Rank-10, mAP를 각각 보고**한다.

## D2 결과 — E0 베이스라인

`src/retrieval/metrics.py`(Market-1501 프로토콜 CMC/mAP, 손계산 케이스로 단위테스트 완료),
`src/data/manifests.py`(MPDD/DogFaceNet 공통 query/gallery 인터페이스), `scripts/eval_reid.py`
구현 완료. ImageNet 사전학습 ResNet50(학습 전혀 없음) 특징 + cosine kNN 결과:

| 데이터셋 | Rank-1 | Rank-5 | Rank-10 | mAP |
|---|---|---|---|---|
| MPDD | 78.8% | 93.3% | 97.1% | 67.1% |
| DogFaceNet | 83.8% | 93.2% | 94.6% | 73.1% |

**예상보다 훨씬 높다** (목표치였던 Rank-1 ≥55%를 학습 없이 이미 초과). 두 가지로 해석된다:
1. 갤러리가 91~278개체로 크지 않아 "학습 없는 일반 특징 + 최근접 이웃"도 실전 이미지 검색보다는
   쉬운 편이다.
2. 더 중요한 시사점: **일반 분류 헤드 파인튜닝(E1)이 오히려 성능을 떨어뜨릴 위험**이 있다.
   Yeon et al. 논문에서도 원본 특징 공간을 유지하는 방식(메타러닝)이 새 클래스에 대한
   전이(fine-tune) 분류보다 훨씬 잘 일반화됨을 보였다 — closed-set CE 학습은 학습에 쓴 개체에는
   맞춰지지만 처음 보는 개체(test set)에는 오히려 안 좋을 수 있다는 뜻. E1 결과가 E0보다 낮게
   나올 수 있다는 걸 이상 신호가 아니라 **예상되는 현상**으로 두고, E2(ProtoNet)가 이를
   회복·상회하는지가 핵심 비교 포인트가 된다.

### D2.7 — E0이 배경(촬영세션)을 외운 건 아닌지 검증 (9/14)

MPDD Rank-1 78.8%가 "같은 촬영 세션의 배경이 힌트가 됐을 가능성"을 실제로 검증했다
(`scripts/diagnose_background_leakage.py`). MPDD의 카메라(camera) 컬럼을 촬영세션(=배경) 대리
지표로 써서, query+gallery 전체 쌍을 무작위 샘플링(약 20만 쌍)해 그룹별 평균 코사인 유사도를 비교:

| 쌍 종류 | 평균 유사도 |
|---|---|
| 같은 개체 · 다른 카메라 (진짜 Re-ID 신호) | **0.687** |
| 다른 개체 · 같은 카메라 (배경 유출 위험 신호) | 0.334 |
| 다른 개체 · 다른 카메라 (대조군) | 0.334 |

**결론**: "다른 개체·같은 카메라" 유사도가 대조군과 완전히 동일(0.334 = 0.334) → **같은 배경이어도
다른 개체면 유사도가 전혀 안 오른다.** 즉 E0의 높은 성능은 배경 유출이 아니라 실제 개체 고유
특징(모양·색·무늬)에서 나온다. 배경 유출 우려는 기각.

  수집한 "공고중" 상태 1,464건은 실제로 필드가 잘 채워져 있었음, 직접 확인한 결과).

**이상치**
- MPDD: 짧은 변 64px 미만 이미지 **52장(3.1%)**을 `usable_for_training=False`로 플래그 처리
  (완전히 삭제하지 않고 표시만 해서, 학습에서는 빼고 정성분석/기록에는 남김).
- 보호소 데이터: 사진이 한 장도 안 받아진 공고 **14건 제거** (1,464 → 1,450건). 데모 갤러리에
  사진 없는 항목은 애초에 쓸모가 없어 삭제가 맞다고 판단.

**원하는 데이터 추출**: 보호소 API 필터링(최근 60일·공고중·개), DogFaceNet ID 기준 80/20 분할
(이미 D1.6에서 완료).

**클래스 불균형**
- MPDD: train ID당 이미지 1~22장 (최대 22배 차이).
- DogFaceNet: 개체당 2~41장, 중앙값 5장 (최대 20배 차이) — 이게 D1.7에서 메타러닝을 채택한
  이유이기도 하다.
- 보호소 데이터: 품종 40종 중 믹스견이 1,186건으로 압도적 → 하드 필터 대신 소프트 신호로만 사용
  (D1의 기존 결정과 동일한 논리).
- **처리 방법 2가지를 코드로 준비**(`src/data/quality.class_balance_weights`):
  1. E1(CE 파인튜닝): 개체별 등장 빈도의 역수를 `WeightedRandomSampler` 가중치로 사용 —
     희귀 개체가 배치에서 덜 등장하지 않도록 보정.
  2. E2(Prototypical Network): 에피소드마다 클래스당 K장을 균일하게 뽑는 구조 자체가 개체별
     보유 이미지 수 차이에 원천적으로 덜 민감함 — 별도 가중치 없이 구조적으로 불균형에 강함.

## D2.6 — Train / Val / Test 데이터 분할 확정

학습 코드를 짜기 전에 분할 기준을 명확히 고정한다. **핵심 원칙: test는 학습·튜닝 과정에서 절대
들여다보지 않는다.** (E0 결과는 이미 test로 산출했지만, 그건 "학습 없는" 특징이라 문제되지 않음 —
이제부터 실제로 가중치를 업데이트하는 E1/E2에 이 원칙이 적용된다.)

| | MPDD | DogFaceNet |
|---|---|---|
| **Train** (가중치 업데이트) | 95 ID / 921장 (저해상도 52장 제외 → 869장 사용) | **948 ID** |
| **Val** (학습 중 모니터링·체크포인트 선택) | 95 ID(=train과 동일 개체) / 111장 — *closed-set*, 수렴 확인용 | **167 ID**(train과 분리) / — *open-set*, 새 개체 일반화 확인용 |
| **Test** (최종 성적표, 손대지 않음) | query 104장 + gallery 521장, 96 ID (train·val과 완전 분리) | **278 ID** (기존 E0 산출에 쓴 그대로, 변경 없음) |

**주의할 비대칭**: MPDD val은 train과 같은 개체라 "학습이 잘 수렴하는지"만 보여주고, 새로운 개체에
대한 일반화는 못 알려준다. DogFaceNet val은 train과 분리된 개체라(방금 `scripts/add_dogfacenet_val_split.py`로
새로 만듦) 훨씬 신뢰도 높은 조기종료·체크포인트 선택 기준이 된다. 보고서에 이 차이를 한계로 명시한다.

**DogFaceNet val 추가 이력**: 원래 train/test 2단계뿐이었음(빈틈). 기존 test 278 ID는 그대로 두고
(이미 E0 수치를 냈으므로), train 1,115 ID 중 167 ID(15%)를 무작위로 떼어 val로 재배정 —
`scripts/add_dogfacenet_val_split.py`, seed=7 (원본 train/test 분할 seed=42와 별개).

## D3 결과 — E1 (ResNet50 + BNNeck + CrossEntropy 파인튜닝)

구현: `src/models/backbones.py`(BNNeckModel), `src/data/train_dataset.py`(MPDD+DogFaceNet 통합
학습셋), `scripts/train_embed.py`(학습 루프). MPDD train(869장, 저해상도 제외) + DogFaceNet
train(5,655장) = 총 6,539장 / 1,042개체를 15 에폭 학습 (M5 MacBook, MPS, 에폭당 ~3분).

**학습 곡선 요약**: train_acc는 에폭 10 이후 99.9%로 사실상 암기 수준까지 도달, MPDD val(closed-set)
정확도는 96.4%까지 상승 — 학습 자체는 정상적으로 수렴함. DogFaceNet val(open-set) Rank-1은
80.8% → 91.0%(에폭 12, 최고)까지 꾸준히 상승 후 유지 → 최고 체크포인트로 저장.

**최종 test 결과 (E0 vs E1 비교, held-out test — 학습·검증에 전혀 안 쓰인 데이터)**:

| 데이터셋 | 지표 | E0 (학습 없음) | E1 (CE+BNNeck) | 변화 |
|---|---|---|---|---|
| MPDD | Rank-1 | 78.8% | **80.8%** | +2.0%p |
| MPDD | mAP | 67.1% | **69.2%** | +2.1%p |
| DogFaceNet | Rank-1 | 83.8% | **87.4%** | +3.6%p |
| DogFaceNet | mAP | 73.1% | **75.6%** | +2.5%p |

**해석 — D2에서 예상했던 "E1이 오히려 나빠질 수 있다"는 우려가 기각됨.** 두 데이터셋·두 지표
모두에서 E1이 E0을 앞섰다. Yeon et al. 논문의 "일반 파인튜닝이 메타러닝보다 훨씬 나쁘다"는
결과와 겉보기엔 배치되는 듯 보이지만, 세팅이 다르다:
- 논문의 "Baseline"은 **처음 보는 새 클래스에 1~5장만으로 분류기를 다시 학습**시키는 진짜
  few-shot 분류 세팅이었다 (매우 불리한 조건).
- 우리 E1은 **학습에 쓴 1,042개체에 대해서만 분류기를 학습**하고, test의 새 개체에는 분류기를
  전혀 다시 학습시키지 않고 임베딩 공간(코사인 유사도)만 그대로 재사용한다 — 여기에 더해
  **BNNeck**(Bag of Tricks, Re-ID 표준 기법)이 분류 경계와 검색 임베딩 사이의 불일치를 줄여줘서,
  일반 파인튜닝의 함정을 상당 부분 피했다고 해석된다.

이 비교(가설 → 실측으로 기각 → 원인 분석)를 Result & Discussion에 그대로 쓰면 좋은 논의거리가 된다.

다음: E2(Prototypical Network)가 E1을 추가로 얼마나 개선하는지가 관건.

## D4 최종 결과 — E0/E1/E2 3자 비교 + DogFaceNet 단독 대조실험 (9/15)

**v3 (500 에피소드, image cache + 실시간 로그 적용 후 완주)**: 16,218초(4.5시간) 소요, 여전히
페이스가 불규칙(디스크/열 스로틀링 추정). val Rank-1은 **에피소드 25에서 83.8%로 정점**을 찍고
이후 다시 회복하지 못함(69~81%대, 최종 76.7%) — v1과 같은 "초반 정점 → 하락" 패턴 재확인.

**최종 test 결과 (E0 vs E1 vs E2, MPDD+DogFaceNet 통합 학습)**:

| 데이터셋 | 지표 | E0 | E1 | E2 |
|---|---|---|---|---|
| MPDD | Rank-1 | 78.8% | **80.8%** | 59.6% |
| MPDD | mAP | 67.1% | **69.2%** | 45.6% |
| DogFaceNet | Rank-1 | 83.8% | **87.4%** | 75.9% |
| DogFaceNet | mAP | 73.1% | **75.6%** | 61.3% |

E2가 두 데이터셋·모든 지표에서 E0(학습 없음)보다도 낮음. 최고 체크포인트가 겨우 25 에피소드
지점(약 3,500장 노출)이라는 점에서, 도메인 불균형(MPDD 9% : DogFaceNet 91%) 때문에 공유
BatchNorm 통계가 DogFaceNet 스타일로 치우쳐 크로스도메인(MPDD) 성능을 깎았을 것이라는
가설을 세우고, 이를 검증하기 위해 **DogFaceNet 단독 학습 대조실험**을 진행했다.

### 대조실험: DogFaceNet만으로 E1·E2 재학습 (`--train-data dogfacenet`)

| 모델 | MPDD Rank-1 | MPDD mAP | DogFaceNet Rank-1 | DogFaceNet mAP |
|---|---|---|---|---|
| E0 (기준) | 78.8% | 67.1% | 83.8% | 73.1% |
| E1 (통합학습) | **80.8%** | **69.2%** | 87.4% | 75.6% |
| E1 (DogFaceNet만) | 77.9% | 61.9% | **88.5%** | 75.5% |
| E2 (통합학습) | 59.6% | 45.6% | 75.9% | 61.3% |
| E2 (DogFaceNet만) | 67.3% | 55.7% | 77.0% | 61.2% |

**해석**:
1. **E1은 통합학습이 정답이었다.** DogFaceNet만으로 학습하면 DogFaceNet 자체 성능은 미세하게
   더 오르지만(87.4→88.5%), MPDD는 학습 때 한 번도 못 봐서 mAP가 E0보다도 낮아진다(69.2→61.9%).
   반대로 MPDD를 섞어 넣어도 DogFaceNet 성능은 거의 안 깎인다(87.4% vs 88.5%, 거의 동일) —
   **두 데이터셋을 합쳐 학습하는 게 사실상 손해 없이 일반화까지 얻는 선택**이었음을 확인.
   D1.6에서 내린 "MPDD+DogFaceNet 통합 학습" 결정이 수치로 뒷받침된다.
2. **E2는 도메인 불균형이 유일한 원인이 아니었다.** DogFaceNet만으로 학습해도(불균형 요인 제거)
   여전히 "에피소드 20에서 정점(79.0%) → 이후 하락" 패턴이 그대로 나타났다(`train_log_E2_dfnonly.csv`).
   즉 원인은 MPDD/DogFaceNet 비율이 아니라, **에피소드 학습 자체(학습률, 프로토타입 추정 방식,
   혹은 매우 적은 K-shot이 갖는 근본적 불안정성)**에 있는 것으로 보인다. 다만 도메인을 단일화하니
   MPDD 쪽 성능은 오히려 개선됐다(Rank-1 59.6→67.3%, mAP 45.6→55.7%) — 불균형이 "유일한
   원인은 아니지만 기여 요인 중 하나"였다는 절충적 결론.
3. **결론: E1(통합학습)을 최종/프로덕션 모델로 채택.** E2는 두 가지 원인(1-shot 프로토타입 잡음,
   도메인 불균형)을 각각 검증했고 둘 다 부분적으로만 영향을 미쳤으며, 근본 원인은 에피소드 학습
   방식 자체의 불안정성으로 남는다 — 이 진단 과정 자체를 Result & Discussion에서 "가설 수립 →
   대조실험으로 검증 → 근본 원인 좁히기"의 사례로 제시한다.

1. 앱 실행 시에는 캐시된 임베딩(빠른 로딩)으로 시작
2. "최신 공고 불러오기" 버튼 클릭 → `fetch_shelter_api.py`와 동일한 로직으로 최근 N일 공고를
   실시간 호출 → 새 사진만 그 자리에서 우리 모델로 임베딩 계산 → 갤러리에 반영
3. 전체를 다시 받지 않고 최근 며칠치로 제한해 응답 시간을 발표 시연에 적합하게(수십 초 이내) 유지

이렇게 하면 "실시간이 아니면 쓸모없다"는 지적에 "새로고침하면 실제 최신 공고가 반영된다"로
정면 대응 가능. 실제 프로덕션 서비스도 초단위 실시간이 아니라 주기적 갱신 방식이 일반적이라
(포인핸드 등도 동일), 이 설계는 실무 기준으로도 정당하다.

### D5 데모 설계 메모 — 사진 전에 메타데이터로 후보군 축소

사용자에게 사진 업로드 전에 **성별·지역·품종·특징**을 먼저 입력받아 후보군을 좁히자는 제안을
실데이터로 검증했다 (`metadata/shelter_manifest_clean.csv`, 1,446건 기준):

| 필터 | 평균 후보군 |
|---|---|
| 없음 | 1,446 |
| 성별만 | ~720 |
| 지역(시도)만 | ~76 |
| **성별 + 지역** | **~34** |

**채택**: 성별(신뢰도 높음, 위험 거의 없음) + 지역(효과 가장 큼, 단 하드 필터 대신 "가까운 지역
우선 + 전국 검색 옵션"으로 완화 — 개체가 타 지역으로 이송되는 경우 대비)을 1차 필터로 쓰고,
그 축소된 후보군 안에서 사진 임베딩 유사도 매칭을 수행한다. 품종은 기존 계획대로 소프트 신호
(믹스견 82%라 하드 필터는 위험), 특징 자유서술 텍스트 매칭은 여유 있으면 스트레치로 추가.

**주의**: 이 필터는 animal.go.kr 실데이터 필드(성별/지역/품종)를 쓰는 **서비스/데모 레이어**다.
MPDD·DogFaceNet 벤치마크에는 이런 메타데이터가 없어 E0~E2의 CMC/mAP 실험 결과에는 영향이 없다 —
모델 성능이 아니라 실사용성을 높이는 별도 층으로 보고서에도 구분해서 설명한다.

### D5.1 — 색상 유사도 보완 (사용자 피드백: "1등 빼면 색깔이 너무 다르다")

데모를 실제로 써본 피드백: 정답(1등)은 잘 찾는데 2~5등 후보가 색깔·품종이 확 다른 경우가 있음.
**원인**: 임베딩은 "같은 개체인지"만 훈련받아서, 오답 후보끼리의 순서(사람이 보기에 그럴듯한
정렬)는 학습 신호가 전혀 없다 — 정답만 잘 맞히면 손실이 0이라, 나머지 순위는 사실상 부작용.

**해결**: 딥러닝 임베딩 코사인 유사도에 **전통적인 색상 히스토그램(HSV Hue×Saturation) 유사도**를
섞었다 (`src/retrieval/color.py`, alpha=0.75). 실제 보호소 leave-one-out 벤치마크로 검증
(`scripts/eval_color_blend.py`):

| 방식 | Rank-1 | mAP |
|---|---|---|
| 임베딩만 | 76.7% | 81.4% |
| **임베딩 75% + 색상 25%** | **79.3%** | **83.6%** |

색깔 보정이 사용자 체감(정성) 개선뿐 아니라 **정량 지표까지 같이 끌어올림** — 근접 매칭
상황에서는 저수준 색상 신호가 딥러닝 임베딩을 보완하는 유의미한 신호였다는 뜻. 데모 앱
(`app/streamlit_app.py`)과 갤러리 캐시(`scripts/build_demo_gallery.py`, 색상 히스토그램도 같이
캐싱)에 반영, 시각 비교(`docs/eda/14_...png` vs `docs/eda/15_..._colorblend.png`)로 확인 완료.

### D5.2 — 개 영역 크롭(배경 제거) 검증 → 기각 (사용자 피드백: "배경 비슷한 사진이 많이 나온다")

**가설**: 임베딩이 배경(마당·바닥 등)까지 함께 학습해서, 배경이 비슷하면 다른 개인데도 높은 순위로
올라온다. COCO 사전학습 탐지기(`fasterrcnn_resnet50_fpn_v2`, `src/retrieval/detect.py`)로 개 영역만
잘라내면 이 오염이 줄어들 것이다.

**1차 검증 (보호소 leave-one-out, `scripts/eval_crop_effect.py`, 같은 세션)**: 크롭이 Rank-1/mAP를
전부 소폭 깎아먹음 (임베딩+색상 기준 Rank-1 79.3%→78.3%, mAP 83.6%→82.7%).

**사용자 지적 (중요)**: 보호소 벤치마크는 "같은 공고" 사진끼리 짝지은 것이라 배경이 사실상 같은
세션 — 실제 서비스는 사용자가 집에서 찍은 사진과 공고 사진을 비교하므로 배경이 항상 다르다. 즉
이 벤치마크는 크롭의 효과를 검증하기에 맞지 않는 셋업이었다.

**2차 검증 (MPDD test, `scripts/eval_crop_effect_mpdd.py`, 서로 다른 카메라/세션 — 실제 배포와 훨씬
가까움)**:

| 크롭 | 방식 | Rank-1 | Rank-5 | Rank-10 | mAP |
|---|---|---|---|---|---|
| 안 함 | 임베딩만 | 80.8% | 93.3% | 98.1% | 69.2% |
| 안 함 | **임베딩 75%+색상 25%** | **82.7%** | **95.2%** | **100.0%** | **73.1%** |
| 함 | 임베딩만 | 76.9% | 92.3% | 94.2% | 67.4% |
| 함 | 임베딩 75%+색상 25% | 82.7% | 93.3% | 98.1% | 71.8% |

실서비스 조건에 가까운 벤치마크로 다시 봐도 결론은 같다 — 크롭은 Rank-1을 그대로 두거나(동률)
Rank-5/10·mAP를 소폭 깎는다. 두 개의 독립된 벤치마크(같은 세션/다른 세션) 모두에서 "도움이 된다"는
신호가 전혀 없었다.

**왜 크롭이 도움이 안 됐는가**: 탐지 자체는 대체로 정상 동작했다(진단 결과 다수가 score 0.9~1.0의
고신뢰도 "개" 판정). 문제는 백본(E1)이 애초에 **배경이 포함된 원본 이미지로 학습**되었다는 점 —
추론 시에만 크롭을 적용하면 학습·추론 간 입력 분포가 달라지는 train/test mismatch가 생기고, 이
손실이 "배경 제거로 얻는 이득"을 상쇄하거나 역전시킨 것으로 보인다. 배경 크롭이 실제로 이득을
보려면 크롭된 이미지로 재학습해야 하는데, 이는 이번 스프린트 범위를 벗어난다.

**결론**: 크롭은 데모(`app/streamlit_app.py`, `scripts/build_demo_gallery.py`)에 통합하지 않는다.
배경 유사도 편향 문제는 D5.1의 색상 블렌딩으로 이미 정량적으로 개선을 확인했고, 크롭은 추가
이득 없이 리스크(도메인 시프트, 탐지 실패 시 크롭 왜곡, 지연시간 증가)만 더한다는 것이 두 벤치마크
공통 결론. 코드(`src/retrieval/detect.py`, `scripts/eval_crop_effect*.py`)는 "시도했으나 근거로
기각"한 기록으로 남겨둔다.

## D6 — 도메인 갭 진단 + E3(품종 사전학습) 채택 (9/16~17)

**계기**: "친구 강아지(회색 푸들, 실내 스마트폰 사진)"를 데모에 직접 넣어보니 Top-5가 전부 믹스견
새끼 사진 — 품종·색깔이 완전히 다름. 사용자 지적: "진짜로 서비스 가능한 걸 만들고 싶다, 처음부터
다시해보자". 무작정 재작업하기 전에 원인부터 진단(사용자 선택: "원인 진단부터").

**진단 1 — shelter 메타데이터(kind_nm/color_cd)로 품종·색상 일치율 정량화**
(`scripts/diagnose_breed_color_coherence.py`): 순종 기준 품종 일치율이 무작위 기준선(2.5%)
대비 9배(22.0%) — 갤러리 **도메인 내부**에서는 임베딩이 품종 신호를 꽤 잘 잡고 있었음.

**진단 2 — 실제 쿼리 사진으로 재현** (`scripts/query_real_photo.py`): 도메인 밖(홈사진) 쿼리는
갤러리 전체 대비 유사도가 평균 수준에서 밋밋하게 깔리고 뚜렷한 스파이크가 없음(최댓값 0.308,
도메인 내부 매칭은 보통 0.6~1.0) → **정체는 아키텍처 결함이 아니라 학습 데이터(MPDD+DogFaceNet)가
실사용 사진의 도메인(실내조명·스마트폰·미용된 반려견)을 전혀 대표하지 못한다는 것.**

**조치**: Stanford Dogs(120품종, 20,580장 — Stanford 원서버가 너무 느려 HF 미러
`amaye15/stanford-dogs` parquet로 전환)로 ResNet50을 품종 분류 먼저 학습(1단계, test_acc
83.0%), 그 백본에서 기존 E1 identity 파이프라인을 그대로 이어 학습(2단계, `E3`) —
`src/models/backbones.py`의 `BNNeckModel(init_backbone_path=...)`, `scripts/train_embed.py
--init-backbone --ckpt-suffix`로 구현. 코드 변경을 최소화해 기존 E1 산출물은 그대로 보존.

**검증 결과**:

| 벤치마크 | E1 | E3 |
|---|---|---|
| MPDD Rank-1 / mAP | 80.8% / 69.2% | **82.7% / 71.1%** |
| DogFaceNet Rank-1 / mAP | 87.4% / 75.6% | 88.5% / 74.5% (오차범위) |
| shelter 순종 품종일치율 | 22.0% | 17.8% (소폭 하락) |
| **실제 사진 쿼리(도메인 밖)** | 전부 믹스견, 곱슬 텍스처 무시 | **Top-1·5가 비숑 프리제(곱슬 텍스처 인식)**, 최대유사도 0.357→0.423 |

MPDD(교차세션)는 개선, DogFaceNet은 오차범위, shelter 내부 순종 일치율만 소폭 하락 — 그런데
정작 원래 문제였던 도메인 밖 사진에서는 뚜렷한 질적 개선. 트레이드오프가 있지만 실사용 문제를
직접 겨냥한 개선이라 판단해 **E3를 프로덕션으로 채택**: `checkpoints/E1_resnet50_bnneck_breedpretrain.pt`로
`app/streamlit_app.py`, `demo_cache/` 갱신.

**한계**: 아직 완전한 해결은 아님 — 비숑 프리제≠푸들이고, 최대유사도(0.42)도 도메인 내부 매칭
수준(0.6+)에는 못 미침. Stanford Dogs도 ImageNet 계열이라 "실내조명·스마트폰" 도메인을 완벽히
대표하진 않음. 다만 방향은 명확히 검증됨(품종 인지 사전학습 → 도메인 밖 일반화 개선) — 시간이
더 있다면 PetFinder류 casual-photo 데이터셋 추가가 다음 후보.

## D7 — Triplet loss(E4) + 색상 히스토그램 V버그 수정 + 멀티샷 쿼리 (9/17)

두 번째 실제 사진(야외, 리드줄 맨 채 보도블록 위)으로 재검증했더니 E3도 여전히 실패 — 갤러리에
진짜 "푸들/회색"으로 태그된 개가 있는데도 순위가 2883마리 중 1552등까지 밀림(임베딩 유사도 0.089,
사실상 무작위). 색상 탓처럼 보였지만 분리 진단 결과 진짜 원인은 둘이었다.

**원인 1 — 색상 히스토그램이 밝기(V)를 뺐던 설계**: 채도만으로는 흰색/회색/검정 같은 무채색을
전혀 구분 못 해 회색 개가 흰색 개들에게 다 밀림. `src/retrieval/color.py`를 H×S 2D(128차원)에서
H×S×V 3D(432차원)로 확장. shelter 벤치마크 회귀 없음(오히려 alpha=0.5~0.6에서 소폭 개선) 확인 후 반영.

**원인 2 (더 큰 원인) — identity CE 손실만으로는 자세/조명 불변성이 안 생김**: 색상을 고쳐도 여전히
실패 → 임베딩 자체가 문제. BNNeck 원 논문(Luo et al., "Bag of Tricks")은 원래 ID loss + Triplet
loss를 함께 쓰는데, 지금까지 이 프로젝트는 ID loss(CE)만 썼다. E3 백본에 배치-하드 Triplet loss
(PK 샘플링, `src/data/episodic.py`의 `group_by_label` 재사용)를 더해 이어 학습 → **E4**
(`scripts/train_embed_triplet.py`).

| | MPDD Rank-1/mAP | DogFaceNet Rank-1/mAP | 인도어 실제사진 | 야외 실제사진(진짜 매칭 개 순위) |
|---|---|---|---|---|
| E1 | 80.8%/69.2% | 87.4%/75.6% | 전부 믹스견 | 866~2243등/2883 |
| E3 | 82.7%/71.1% | 88.5%/74.5% | 비숑 프리제 | 866~2243등/2883 |
| **E4** | **87.5%/72.5%** | 87.1%/**79.3%** | **정확히 "푸들"(Top-1,2)** | **271~2128등**(최고순위 대폭상승) |

모든 벤치마크에서 최고 또는 동급 최고, 실제 사진도 뚜렷이 개선 — **E4를 프로덕션으로 채택**
(`checkpoints/E1_resnet50_bnneck_breedpretrain_triplet.pt`). 다만 야외/극단적 클로즈업처럼 자세
변화가 큰 사진은 여전히 Top-5 밖 — 완전한 해결은 아니다.

**멀티샷 쿼리 (사용자 제안)**: "사용자가 사진 여러 장을 올리게 하면 어떨까?" — DogFaceNet으로
leave-K-out 검증(`scripts/eval_multiquery.py`, K장 평균 임베딩 vs 갤러리 나머지):

| K(쿼리 장수) | Rank-1 | mAP |
|---|---|---|
| 1장(기존) | 87.1% | 79.3% |
| 2장 | **95.4%** | **89.1%** |
| 3장 | 95.8% | 92.5% |
| 5장 | 93.4% | 93.1% |

2장만 올려도 Rank-1 +8.4pp, mAP +9.9pp — 단일 사진의 자세/조명 편향이 평균으로 상쇄된다는 뜻.
3장부터는 사실상 포화. 데모 앱에 최대 5장 업로드 + 임베딩·색상히스토그램 평균 반영
(`app/streamlit_app.py`의 `embed_query_multi`).

**실사용자 재검증 (5장 업로드)**: 사용자가 실제로 회색 푸들 사진 5장(집·마당, 배경 제각각)을
올려 재테스트 — Top-5엔 여전히 안 들었지만, 갤러리에 있는 진짜 매칭견 순위가 271등(1장 쿼리)에서
**86등/2883(상위 3%)**까지 올라감. 업로드 사진 5장 서로간의 임베딩 유사도가 0.27~0.48로 낮다는 것도
확인 — 자세/배경이 다르면 "같은 개"라는 확신이 아직 약함(triplet loss로도 완전히는 안 없어지는
근본적 한계). Top-5 컷오프가 실사용 관점에서 너무 빡빡하다고 판단해 **Top-10으로 확대**
(`TOP_K = 10`, 5열×2행 그리드).

## D8 — Top-10 확대 재검증 + 빠른 개선 3종 시도(모두 실패) → 모델 작업 마무리 (9/17)

Top-10으로 넓힌 뒤 사용자가 같은 5장으로 재테스트 — **여전히 안 뜸**. 재확인해보니 "86등"은
**사진 단위** 순위였고, 실제 앱처럼 개체당 최고 사진 하나로 합쳐 다시 매기면 진짜 매칭견은
**58등 / 90등(전체 1,446마리 중)** — Top-10보다 한참 아래였다(이전 보고가 부정확했음, 정정).

재학습 없이 시도해볼 수 있는 빠른 개선 3가지를 테스트했으나 전부 효과 없음:

| 시도 | 결과 |
|---|---|
| 갤러리도 개체당 여러 사진을 평균해 프로토타입화 | 오히려 순위 악화 (58→74, 90→265) — 갤러리 쪽은 개체당 사진이 2장뿐이라 평균이 신호보다 노이즈를 더 더함 |
| 품종(푸들)만 필터링해서 후보 축소 | 51마리 중에서도 25등/32등 — 품종 좁혀도 안 뜸 |
| 임베딩:색상 blend 비율(alpha) 재조정 | 기존 0.75가 오히려 제일 나음(0.5/0.3/0.1은 다 더 나쁨) |

**결론**: 품종 필터링까지 해도 안 뜬다는 게 결정적 증거 — 색상·품종 신호의 가중치 문제가 아니라
**"이 개체를 다른 자세/배경 사진에서 재인식하는" 임베딩 자체의 판별력이 아직 부족**하다는 뜻.
이건 파라미터 조정이 아니라 더 많은 실사용 도메인 데이터나 더 정교한 metric learning이 필요한
영역이라 판단, 남은 일정(발표 9/22)을 고려해 **모델 개선 작업은 여기서 마무리**하고 정성분석·
보고서·발표자료 준비로 전환하기로 결정. (E4 + Top-10 + 멀티샷 업로드 상태를 최종 제출 버전으로
유지, 이 리포트 자체가 실패 사례 분석 자료로도 활용 가능.)
