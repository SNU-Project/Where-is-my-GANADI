## 1. 서론

### 1.1 문제 정의

보호소에 들어온 유기견 사진과, 반려인이 가지고 있는 실종견 사진을 서로 매칭해주는 서비스
**"찾아줘, 가나디"**를 만든다. 겉보기엔 "개 사진 두 장이 같은 개인지 판별"하는 문제이지만,
분류(classification) 문제로 풀 수 없다는 게 핵심 설계 포인트다 — 서비스에 새로 들어오는
보호소 공고와 실종견은 학습 때 전혀 보지 못한 개체이기 때문에, "학습한 클래스 중 하나를
맞히는" 닫힌 문제가 아니라 **한 번도 본 적 없는 개체를 임베딩 유사도로 찾아내는 열린(open-set)
검색(retrieval) 문제**다. 이는 사람 재식별(Person Re-Identification)과 정확히 같은 문제
구조이며, 우리는 이 분야의 표준 평가 프로토콜(CMC, mAP)과 기법(BNNeck, Triplet loss)을
그대로 가져와 적용했다.

### 1.2 서비스 개요

사용자가 실종견 사진(최대 5장)을 업로드하면, 국가동물보호정보시스템(animal.go.kr)의 실제
유기견 공고 갤러리 중 가장 비슷한 개체 Top-10을 찾아 보여준다. 최종 판단은 보호소 방문·연락을
통해 사람이 하도록 명시하고, 서비스는 "후보 제시"까지만 담당한다.

### 1.3 기여

- 사람 Re-ID 표준 기법(BNNeck, Triplet loss, CMC/mAP 평가)을 동물(개) 재식별에 적용하고,
  두 개의 이질적 데이터셋(전신·포즈 위주 MPDD, 얼굴 클로즈업 DogFaceNet)을 통합 학습해 교차
  일반화를 검증했다.
- E0(무학습 베이스라인)부터 E4(품종 사전학습+Triplet loss)까지 5단계 모델을 정량 비교하고,
  각 단계의 채택/기각을 가설→실험→해석의 과정으로 투명하게 기록했다.
- 실제 서비스 시나리오(학습 도메인 밖의 스마트폰 사진)로 반복 재현 테스트를 수행해, 벤치마크
  지표만으로는 드러나지 않는 도메인 갭·주의 실패·판별력 한계를 실증적으로 발견했다.
- 실사용 데이터(animal.go.kr) 기반 Streamlit 데모를 구현해 전체 파이프라인이 실제로 동작함을
  확인했다.

## 2. 관련 연구

- **사람 재식별(Person Re-ID)**: Market-1501 프로토콜(CMC Rank-k, mAP)이 이 분야 표준 평가
  방식이며, 우리 프로젝트의 평가 지표(`src/retrieval/metrics.py`)로 그대로 채택했다.
- **BNNeck — Luo et al., "Bag of Tricks and a Strong Baseline for Deep Person
  Re-identification" (2019)**: GAP → BatchNorm(bias 없음) → 분류기 구조로, 학습 시 ID
  손실(CE)로 분류기를, 추론 시 BN을 통과한 특징으로 검색하는 기법. 원 논문은 **ID loss +
  Triplet loss**를 함께 쓰는 것을 표준 레시피로 제시하는데, 이 프로젝트는 D7 이전까지
  ID loss만 사용하고 있었다는 것을 실패 진단 과정에서 발견했다(6.3절).
- **Prototypical Networks — Snell et al. (2017)**: 클래스 프로토타입(지지집합 임베딩 평균)까지의
  거리로 분류하는 소수샷 메타러닝 기법. E2에서 채택했으나 최종적으로는 기각했다(5.3절).
- **연수민 외, "Few-Shot Dog Face Identification via Meta-Learning" (Journal of KIIT,
  2025)**: 정확히 우리가 쓰는 DogFaceNet으로 실험한 선행연구로, 개체당 이미지가 극히 적은
  상황(중앙값 5장)에서 일반 전이학습 파인튜닝(1-shot 18.3%)이 메타러닝(Meta-DeepBDC, 1-shot
  64.0%)에 크게 뒤처짐을 보였다. 이 결과가 E2(ProtoNet) 채택의 직접적 근거였다.
- **DogFaceNet (Mougeot et al.)**: 개 얼굴 재식별을 위한 공개 데이터셋·모델. 우리는 이 중
  데이터셋만 별도로 가져와 사용했다(HuggingFace `dimidagd/DogFaceNet_224resize`).

### 3.1 데이터셋 구성

| 데이터셋 | 역할 | 규모 | 출처/라이선스 |
|---|---|---|---|
| **Multi-pose Dog Dataset (MPDD)** | 전신·다자세 학습·평가 | 191개체 / 1,657장 | 공개 데이터셋 |
| **DogFaceNet** | 얼굴 클로즈업 학습·평가(메인 학습 데이터) | 1,393개체 / 8,363장 | HuggingFace, MIT |
| **animal.go.kr 유기견 공고** | 데모 갤러리 + 실사용 도메인 검증 | 1,446건 / 사진 2,883장 | 국가동물보호정보시스템 공공 API |
| **Stanford Dogs** | 품종 분류 사전학습(E3) | 120품종 / 20,580장 | Stanford Vision Lab (ImageNet 기반) |

**MPDD**를 고른 이유는 실제 다자세(포즈 변화) 상황을 담고 있어 재식별 강건성 검증에 적합하기
때문이고, **DogFaceNet**을 추가한 이유는 animal.go.kr 실사진의 약 1/3이 얼굴 클로즈업이라
전신 위주 데이터만으로는 부족하다는 EDA 관찰 때문이다(D1.6). MPDD와 DogFaceNet은 개체가
전혀 겹치지 않아 ID 네임스페이스만 분리하면 하나의 학습 풀로 합칠 수 있었다.

### 3.2 EDA 핵심 발견

- MPDD: 짧은 변 128px 미만 이미지가 30.6%, 64px 미만도 3.1% — 저해상도 대응이 필요했다.
- animal.go.kr: 믹스견이 81.8%로 압도적 — 품종은 하드 필터가 아니라 소프트 신호로만 사용하기로
  결정.
- animal.go.kr 실사진에서 이모지 스티커, 사람 팔, 어수선한 배경이 관찰됨 — MPDD/DogFaceNet
  대비 실제 도메인 갭이 존재할 가능성을 이 시점부터 예견했다(실제로 D6~D8에서 이 갭이 핵심
  실패 원인으로 확인됨).
- 같은 개체도 자세·구도 변화가 큼 — 포즈 강건 임베딩의 필요성을 데이터로 확인.

### 3.3 전처리

| 항목 | 처리 |
|---|---|
| 결측치 | 이미지 파일 손상 여부 점검(0건), 보호소 텍스트 필드(품종·색상·나이 등) 결측 점검(0건) |
| 이상치 | MPDD 저해상도(짧은 변 <64px) 52장(3.1%)을 학습에서 제외(기록은 유지); 보호소 공고 중 사진 없는 14건 삭제(1,464→1,450→1,446) |
| 클래스 불균형 | E1: 개체별 등장 빈도 역수로 `WeightedRandomSampler` 가중치 부여; E2: 에피소드 샘플링 구조 자체가 불균형에 원천적으로 덜 민감 |

## 4. 방법

### 4.1 문제 정식화

개체 $i$의 이미지 $x$를 임베딩 함수 $f_\theta$로 $d$차원 벡터 $f_\theta(x)$에 매핑하고,
코사인 유사도로 순위를 매기는 검색(retrieval) 문제로 정식화한다. 학습 때 본 개체 집합과
평가(쿼리/갤러리) 때의 개체 집합이 겹치지 않는 **open-set** 조건을 전 실험에 일관되게
적용했다.

### 4.2 모델 아키텍처 — BNNeck

```
입력 이미지 → ResNet50(ImageNet 사전학습) conv stack → GAP → 2048-d 특징
    → BatchNorm1d(bias 없음) → bn_feat(검색에 사용) → Linear 분류기 → logits(학습에만 사용)
```
학습 시에는 `bn_feat`을 분류기에 통과시켜 CrossEntropy(E1~E4 공통) 및 Triplet(E4)
손실을 계산하고, 추론 시에는 분류기를 버리고 `bn_feat`을 그대로 코사인 유사도 검색에 쓴다.

### 4.3 모델 반복 (E0 → E4)

| | 방법 | 채택 여부 |
|---|---|---|
| **E0** | ImageNet 사전학습 ResNet50 특징 그대로, 학습 없이 cosine kNN | 베이스라인 |
| **E1** | ResNet50 + BNNeck + CrossEntropy 파인튜닝 (MPDD+DogFaceNet 통합 학습) | 1차 채택 |
| **E2** | ResNet50 + Prototypical Network 에피소드 학습(20-way, 적응형 K-shot) | 기각 (5.3절) |
| **E3** | Stanford Dogs 120품종 분류로 먼저 사전학습한 백본 → E1과 동일한 방식으로 이어 학습 | 중간 채택 |
| **E4** | E3 백본 + 배치-하드 Triplet loss 추가 | **최종 채택** |

**E3·E4를 도입한 이유**(자세한 진단 과정은 6절): E1은 벤치마크상 최고 성능이었지만, 실제
스마트폰 사진으로 데모를 테스트하자 품종·색깔이 완전히 다른 개가 상위권에 나오는 문제가
드러났다. 원인을 추적한 결과 (1) 학습 데이터가 실사용 도메인(실내조명·스마트폰)을 대표하지
못하고, (2) identity CE 손실만으로는 자세·조명 불변성이 학습되지 않는다는 두 가지 근본
원인을 찾았고, 각각 품종 분류 사전학습과 Triplet loss 추가로 대응했다.

### 4.4 손실 함수·하이퍼파라미터

| | 손실 | 주요 하이퍼파라미터 |
|---|---|---|
| E1/E3 | CrossEntropy (label smoothing 0.1) | AdamW, lr 3.5e-4, weight decay 5e-4, 15 epoch, batch 32, WeightedRandomSampler |
| E2 | Prototypical loss (softmax over 프로토타입 거리) | 20-way, support 최대 5장/query 최대 4장(적응형), 500 episode, lr 1e-4 |
| E3 사전학습 | CrossEntropy (품종 120-way) | AdamW, lr 3.5e-4, 15 epoch (Stanford Dogs) |
| **E4** | CrossEntropy + **배치-하드 Triplet**(margin 0.3, 가중치 1.0) | PK 샘플링(P=16개체×K=4장), AdamW lr 3.5e-4, 1,500 step |

색상 히스토그램 블렌딩(D5.1, 4.5절)과 멀티샷 쿼리(D7, 6.4절)는 모델과 별개로 검색 단계에서
추가한 보완 기법이다.

### 4.5 검색 단계 보완 — 색상 히스토그램 블렌딩

임베딩은 "진짜 정답(같은 개체)"을 찾는 데는 강하지만, 오답 후보끼리의 순서(색깔이 완전히
다른 개가 상위권에 나오는 문제)에는 학습 신호가 없다. HSV Hue×Saturation×Value 3D
히스토그램(교집합 유사도)을 임베딩 코사인 유사도와 `0.75:0.25`로 블렌딩해 보완했다
(`src/retrieval/color.py`). 원래 밝기(V)를 뺀 2D(H×S) 버전으로 시작했으나, 흰색/회색/검정을
구분 못 하는 버그를 D7에서 발견해 3D로 수정했다.

## 5. 실험

### 5.1 평가 설정·지표

CMC(Cumulative Matching Characteristic) Rank-1/5/10과 mAP(mean Average Precision) —
Market-1501 프로토콜을 그대로 적용(`src/retrieval/metrics.py`, 손계산 케이스로 단위테스트
완료). MPDD·DogFaceNet 각각 독립된 test set에 대해 보고한다.

### 5.2 결과 표 (전체 실험, `metadata/results.csv`)

| 모델 | MPDD Rank-1 | MPDD mAP | DogFaceNet Rank-1 | DogFaceNet mAP |
|---|---|---|---|---|
| E0 (베이스라인, 학습 없음) | 78.8% | 67.1% | 83.8% | 73.1% |
| E1 (CE+BNNeck, 통합학습) | 80.8% | 69.2% | 87.4% | 75.6% |
| E1 (DogFaceNet만 학습, 대조실험) | 77.9% | 61.9% | 88.5% | 75.5% |
| E2 (ProtoNet, 통합학습) | 59.6% | 45.6% | 75.9% | 61.3% |
| E2 (DogFaceNet만 학습, 대조실험) | 67.3% | 55.7% | 77.0% | 61.2% |
| E3 (품종 사전학습 + CE) | 82.7% | 71.1% | 88.5% | 74.5% |
| **E4 (E3 + Triplet, 최종)** | **87.5%** | **72.5%** | 87.1% | **79.3%** |

**baseline(E0) vs 파인튜닝(E1) 비교**: 두 데이터셋·두 지표 모두에서 E1이 E0을 앞선다
(MPDD Rank-1 +2.0%p, mAP +2.1%p; DogFaceNet Rank-1 +3.6%p, mAP +2.5%p). 다만 5.4절에서
보듯 이 우위가 모든 도메인에서 성립하지는 않는다.

### 5.3 E2(Prototypical Network) 기각 과정

Yeon et al.(2025) 선행연구에 근거해 저샷(개체당 이미지 극소) 상황에 유리하다고 기대했으나,
실측 결과 두 데이터셋·모든 지표에서 **E0(무학습)보다도 낮았다**. 검증 곡선이 에피소드
20~25 근방에서 정점을 찍은 뒤 회복하지 못하는 과적합 패턴이 반복 관찰됐다. 가설 두 가지를
세워 대조실험으로 검증했다:

1. *"MPDD:DogFaceNet 9:91 비율 때문에 공유 BatchNorm 통계가 한쪽으로 치우쳤다"* → DogFaceNet
   단독 재학습으로 검증. MPDD 성능은 개선됐지만(Rank-1 59.6%→67.3%) 여전히 E0보다 낮고, 동일한
   과적합 패턴이 재현됨 → **부분적으로만 맞음**.
2. *"1-shot 프로토타입이 너무 잡음이 심하다"* → support를 최대 5장으로 늘렸으나 문제 패턴은
   유지됨.

**결론**: 근본 원인은 도메인 불균형이 아니라 에피소드 학습 방식 자체(적은 K-shot에서의
프로토타입 추정 불안정성)로 좁혀졌고, E1을 최종 채택했다. 이 과정(가설→대조실험→원인 좁히기)
자체를 결과 해석의 사례로 제시한다.

### 5.4 도메인에 따라 뒤집히는 baseline 우위 (중요한 발견)

실제 보호소 사진으로 leave-one-out 재현 테스트(같은 공고의 사진 두 장 중 하나를 쿼리로)를
했을 때는 결과가 **역전**된다:

| 모델 | Rank-1 | mAP |
|---|---|---|
| E0 (베이스라인) | **79.5%** | **84.1%** |
| E1 (파인튜닝) | 76.7% | 81.4% |

MPDD/DogFaceNet에서는 E1이 E0을 이겼지만, animal.go.kr 실사진에서는 반대로 E0(범용
ImageNet 특징)이 E1(MPDD/DogFaceNet에 특화된 파인튜닝)을 앞선다. **파인튜닝이 학습 도메인
성능은 올리지만 그 대가로 다른 도메인에 대한 일반화를 일부 희생할 수 있다**는 것을 보여주는
결과로, 이후 D6~D8에서 본격적으로 파고든 "도메인 갭" 문제를 가장 먼저 암시한 실험이었다.

## 6. 분석 (정성분석)

전체 내용은 `docs/03_정성분석.md`에 히트맵 이미지와 함께 정리되어 있다. 핵심만 요약한다.

### 6.1 배경 크롭 시도 → 기각

"배경이 임베딩을 오염시킨다"는 가설로 COCO 사전학습 탐지기로 개 영역만 크롭해 재평가했으나,
같은 세션(보호소) 벤치마크·교차 세션(MPDD) 벤치마크 둘 다에서 성능이 오히려 하락했다.
원인은 학습 때는 배경 포함 이미지를, 추론 때만 크롭된 이미지를 쓰는 **train/test
mismatch**로 판단, 크롭은 폐기했다.

### 6.2 실사진 재현 테스트로 발견한 진짜 도메인 갭

사용자의 실제 반려견(회색 푸들) 사진으로 데모를 직접 테스트하자 Top-5가 전부 믹스견으로
나왔다. 갤러리 **내부**에서는 품종/색상 신호가 무작위 대비 9배 높게 유지되는데(정상), 이
도메인 **밖** 사진에 대해서는 갤러리 전체 유사도가 밋밋하게 깔리며 뚜렷한 스파이크가 없었다
(최댓값 0.31, 도메인 내부 매칭은 보통 0.6 이상). 학습 데이터(MPDD+DogFaceNet)가 실사용
도메인(실내조명·스마트폰·미용된 반려견)을 대표하지 못한다는 결론에 이르렀고, 이를 보완하기
위해 Stanford Dogs로 품종 분류 사전학습(E3)을 도입했다.

### 6.3 두 번째 실사진에서 찾은 두 가지 독립된 원인

야외 사진으로 재검증했을 때 E3도 여전히 실패했다. 임베딩·색상 기여도를 분리 진단해 두 개의
서로 다른 원인을 확인했다:

1. 색상 히스토그램이 밝기(V)를 뺀 설계라 흰색/회색/검정을 구분하지 못했다(4.5절 수정).
2. **더 근본적인 원인**: BNNeck 원 논문은 ID loss와 Triplet loss를 함께 쓰는데, 이 프로젝트는
   그동안 ID loss(CE)만 사용하고 있었다. Triplet loss가 없으면 "분류 경계를 나누는" 신호만
   있을 뿐 "같은 개체는 가깝게, 다른 개체는 멀게"라는 직접적인 거리 신호가 없어, 자세·조명이
   달라지면 임베딩이 쉽게 흔들린다. 이 진단에 따라 배치-하드 Triplet loss를 추가한 것이
   E4다.

### 6.4 활성화 히트맵 — "배경 편향"은 일관된 문제가 아니었다

임베딩의 마지막 conv 특징맵에서 채널 방향 L2 norm을 구해 만든 활성화 히트맵으로 모델이
어디에 반응하는지 직접 확인했다(open-set 검색 모델은 고정 분류 타깃이 없어 전통적
Grad-CAM 대신 이 방법을 사용). MPDD 성공 사례와 실사진 인도어 사례 2건에서는 모델이 배경에
전혀 반응하지 않고 개 얼굴·몸통에 정확히 집중했지만, 야외 잔디밭 사진 한 건에서는 배경
텍스처에 개 얼굴보다 더 강한 활성화 스파이크가 나타났다. 즉 **"배경에 흔들린다"는 단일
원인이 아니라, 사진마다 정도가 다르게 나타나는 두 가지 서로 다른 실패 모드**(주의 실패 vs
판별력 실패)가 섞여 있다는 것이 최종 결론이다.

### 6.5 재학습 없는 빠른 개선 3종 시도 — 전부 효과 없음

같은 개체(회색 푸들, 갤러리에 품종·색상까지 정확히 일치하는 개체가 실존)를 대상으로 재학습
없이 시도할 수 있는 개선을 모두 테스트했다.

| 시도 | 결과 |
|---|---|
| 갤러리도 개체당 여러 사진을 평균해 프로토타입화 | 순위 악화(58→74등, 90→265등) |
| 품종(푸들)만 필터링해서 후보 축소 | 51마리 중에서도 25등/32등 |
| 임베딩:색상 blend 비율(alpha) 재조정 | 기존 0.75가 이미 최적 |

품종을 완전히 좁혀도 안 됐다는 것이 결정적 증거였다 — 가중치나 필터링 문제가 아니라
**임베딩 자체의 개체 재인식 판별력**이 병목이라는 뜻이다. 이 지점에서 모델 개선 작업을
마무리하기로 결정했다(6.6절).

### 6.6 멀티샷 쿼리 — 부분적이지만 유효한 완화책

같은 개의 사진을 여러 장 평균하면 자세·조명 편향이 상쇄될 것이라는 가설(사용자 제안)을
DogFaceNet leave-K-out 벤치마크로 검증했다.

| 쿼리 사진 장수 | Rank-1 | mAP |
|---|---|---|
| 1장(기존) | 87.1% | 79.3% |
| 2장 | **95.4%** | **89.1%** |
| 3장 | 95.8% | 92.5% |
| 5장 | 93.4% | 93.1% |

2장만 올려도 Rank-1 +8.4%p, mAP +9.9%p로 뚜렷하게 개선되고 3장부터 포화된다. 데모에 최대
5장 업로드 기능으로 반영했다. 다만 실제 5장(배경 제각각)으로 재검증하자 갤러리의 진짜
매칭견이 순위 271등→86등(사진 단위)까지는 올랐지만, 개체 단위로 재정렬하면 58등/90등(전체
1,446마리 중)으로 여전히 Top-10 밖이었다 — 멀티샷은 확실한 개선이지만 완전한 해결책은 아니다.

## 7. 데모

`app/streamlit_app.py`, 실행: `streamlit run app/streamlit_app.py`.

**아키텍처**: `scripts/build_demo_gallery.py`가 animal.go.kr 실제 공고 사진 2,883장의

사진(들)만 그 자리에서 임베딩·히스토그램을 계산해 비교한다.

**기능**:
- 최대 5장 업로드 → 임베딩·색상 히스토그램 평균(멀티샷 쿼리)
- 사이드바 성별·지역(시도) 필터로 후보군 사전 축소 (필터에 맞는 후보가 없으면 자동으로 전체
  검색으로 폴백)
- Top-10 후보 카드: 사진, 유사도(임베딩 75%+색상 25% 블렌딩), 품종·성별·나이, 보호소명·주소·
  전화, 특징, 공고번호
- "참고용 후보이며 최종 확인은 보호소 방문·연락 필요"를 상단에 명시

실제 브라우저로 업로드→검색→필터 전체 플로우가 정상 동작함을 확인했다(체크포인트 로드,
갤러리 캐시 로드, 검색 응답 시간 1초 이내).

## 8. 결론 및 향후 과제

### 8.1 결론

- 사람 Re-ID 기법(BNNeck, Triplet loss)을 동물 재식별에 적용해, 두 이질적 데이터셋을 통합
  학습하고 E0 대비 뚜렷한 성능 향상(MPDD Rank-1 +8.7%p, DogFaceNet mAP +6.2%p, E0→E4
  기준)을 얻었다.
- 벤치마크 지표만으로는 드러나지 않는 실사용 실패(도메인 갭, 색상 히스토그램 버그, Triplet
  loss 누락)를 실제 사진 재현 테스트로 찾아내고, 각각을 정량적 근거로 검증한 뒤 개선했다.
- 크롭 배경 제거, 갤러리 프로토타입 평균, 품종 필터링, blend 비율 재조정 등 여러 시도가
  실패했다는 것 자체가 유의미한 결과다 — 남은 병목은 파라미터 튜닝이 아니라 **임베딩의
  개체 재인식 판별력**(자세·조명 불변성)이라는 것을 여러 각도에서 실증했다.
- 멀티샷 업로드(최대 5장)와 Top-10 확대라는 UX 레벨 완화책으로 실사용 체감 실패율을
  낮췄다.

### 8.2 한계

- 실제 "수개월 뒤, 완전히 다른 환경에서 재회"하는 진짜 실종 시나리오에 대한 정량 평가는
  하지 못했다 (animal.go.kr 데이터는 leave-one-out 근접 매칭만 가능).
- 실사진 재현 테스트는 표본 수가 2건(포즈 다른 사진 각 5장)으로 매우 적어, 통계적으로
  일반화하기보다는 실패 모드를 발견하는 용도로만 사용했다.
- MPDD val은 train과 같은 개체(closed-set)라 수렴 확인용으로만 쓰였고, 새 개체 일반화는
  DogFaceNet val로만 확인했다는 비대칭이 있다.

### 8.3 향후 과제

- 크롭 기반 배경 제거를 처음부터 재학습에 반영(추론 시에만 적용하는 현재 방식의
  train/test mismatch 해소).
- PetFinder류 "일상 사진" 데이터셋을 추가해 자세·조명 다양성 확보.
- 더 강한 augmentation(원근 왜곡, 강한 색상 지터)으로 자세 불변성을 직접 학습 신호에 포함.
- "이 개의 최신 상태 확인"(desertion_no 단건 조회), "최신 공고 불러오기" 실시간 새로고침 등
  설계는 됐으나 시간상 미구현된 기능 마무리.
